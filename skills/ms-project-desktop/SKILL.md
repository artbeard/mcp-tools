# Microsoft Project Desktop

Перед работой с локальным планом вызывай MCP tool `ms_project_desktop` с `action: "status"`. Он возвращает факты об открытых окнах Microsoft Project и путях к `.mpp`.

Для дерева работ используй `action: "outline"`. Ответ содержит имя и путь плана, а также задачи с номером в иерархии, уровнем, признаком сводной задачи, названием и датами. Действие работает только когда открыт ровно один `.mpp`.

Для изменения существующей задачи сначала вызывай `ms_project_preview_task_update`. Передавай `task_unique_id` и только планируемые поля `name`, `start`, `finish` или `duration`. Инструмент не записывает данные, но показывает исходное состояние, предлагаемые значения и предупреждения о зависимостях.

Для всех новых операций используй `ms_project_preview_change` с полем `request` — JSON. После того как его результат показан пользователю и пользователь явно подтвердил именно этот JSON, вызови `ms_project_apply_change` с неизменённым `request` и `confirmed: true`.

Поддерживаются следующие запросы:

- ресурс: `{"kind":"resource","operation":"create","name":"Аналитик","max_units":1}`; для `update` и `delete` указывай `resource_unique_id`;
- задача: `{"kind":"task","operation":"create","name":"Новая работа","parent_unique_id":87}`; для `update` и `delete` указывай `task_unique_id`; у `create` и `update` допустимы `name`, `manual`, `milestone`, `start`, `finish`, `duration`, `constraint_type`, `constraint_date`. Для вехи передавай `milestone:true` и дату `start`, не задавая `duration`;
- расписание: `{"kind":"schedule","operation":"update","task_unique_id":91,"duration":"5d"}`; для связей используй `link` или `unlink` с `task_unique_id` (последователь) и `predecessor_unique_id`; для временной шкалы — `timeline_add` или `timeline_remove` с `task_unique_id`;
- назначение: `{"kind":"assignment","operation":"add","task_unique_id":91,"resource_unique_id":12,"units":0.5}` либо `operation:"remove"` без `units`.

`UniqueID` — постоянный идентификатор объекта в конкретном плане; получай его из `outline`, не подставляй номер строки или название. `max_units` и `units` задаются долей занятости: `1` — 100 %, `0.4` — 40 %.

Для `schedule:link` необязательное поле `link_type` задаёт связь: `0` — окончание–окончание,
`1` — окончание–начало (по умолчанию), `2` — начало–окончание, `3` — начало–начало.
Пример: `{"kind":"schedule","operation":"link","task_unique_id":91,"predecessor_unique_id":87,"link_type":0}`.
При замене типа существующей связи сначала отдельно согласуй её удаление. Для тестов,
идущих по мере разработки, связь окончания может предотвратить преждевременное завершение
без требования начинать все проверки только после всей разработки. Она не является оценкой
дополнительных часов проверки. Перед сохранением связи инструмент проверяет сохранность
часов, процентов назначений и фактических дат всех несводных задач.

`outline` возвращает входящие связи `dependencies` по UniqueID с типом и задержкой в минутах,
а также `actual_start`, `actual_finish`, `stop`, `resume` и `remaining_duration_minutes`.
Наличие выполненных часов не означает, что записанные фактические даты корректны:
проверяй их перед перепланированием оставшейся работы; не исправляй табель предположениями.

## Человекочасы и пересчёт длительности

`outline` также возвращает `work_hours`, `actual_work_hours`, `remaining_work_hours`,
`duration_minutes`, `task_type`, `effort_driven` и список `assignments` с часами и единицами
каждого назначения. Часы — числовые значения; преобразование в минуты COM выполняет инструмент.

- Часы задачи: `{"kind":"schedule","operation":"update","task_unique_id":91,"work_hours":160,"task_type":0}`.
- Часы существующего назначения: `{"kind":"assignment","operation":"update","task_unique_id":91,"resource_unique_id":12,"work_hours":80}`.
- Новый исполнитель сразу с часами: `{"kind":"assignment","operation":"add","task_unique_id":91,"resource_unique_id":12,"units":0.3,"work_hours":48}`.
  Поддерживается у задачи с фиксированными единицами и `effort_driven:false`; существующие
  часы других назначений и факт сохраняются. При совпадении ресурса используй `update`.
- Для существующего назначения `update` также принимает `units` вместе с `work_hours`.
  Изменение процентов поддерживается только при фиксированных единицах и отсутствии факта
  в задаче. Часы и новые проценты должны быть явно согласованы; остальные назначения сохраняются.
- Для смены только процентов с сохранением текущих часов используй
  `{"kind":"assignment","operation":"update","task_unique_id":91,"resource_unique_id":12,"units":1}`.
  При фиксированных единицах это поддерживается и у задач с фактом. Инструмент меняет процент
  и сохраняет остаток назначения без округления входных часов до минут; до сохранения проверяет
  общие и фактические часы, фактические даты всех несводных задач и остальные назначения.
  Не добавляй `work_hours` или другие изменения в этот запрос. У выполненной задачи смена процента
  не означает пересчёт исторического табеля; при нарушении сохранности инструмент пытается отменить изменение.
- Общие и фактические часы назначения: `{"kind":"assignment","operation":"update","task_unique_id":91,"resource_unique_id":12,"work_hours":10,"actual_work_hours":8}`.
  Остаток в этом примере — 2 часа. Факт задаётся только вместе с общим объёмом на существующем
  назначении; уменьшение записанного факта запрещено. Распределение между исполнителями
  согласуй с пользователем, не выводи его из процентов занятости. Project сам распределяет
  суммарный факт по дням; это не подтверждение дат фактического выполнения или табеля.
- Тип задачи задаётся явно: `task_type:0` — фиксированные единицы, `1` — фиксированная
  длительность, `2` — фиксированные трудозатраты. Для изменения `effort_driven` используется
  логическое значение в запросе обновления задачи; тип `2` всегда требует `true`.

Для пересчёта дней при сохранении процентов назначений используй автоматическое планирование
и фиксированные единицы. Если задача ручная, добавь `manual:false` только когда это входит
в согласованное изменение. Без исполнителей часы сохраняются, но длительность по ним не определяется.
Ввод общего объёма задачи распределяет часы между назначениями по правилам Project; при разных
видах работ задавай часы назначений отдельно. Не подменяй человекочасы полным итогом декомпозиции,
если часть работ вынесена в отдельные аналитические или тестовые задачи.

Не меняй одновременно часы и даты, длительность, ограничения или признак вехи. Запрещены
отрицательные часы, часы меньше фактически выполненных, положительные часы вехи и изменение
часов сводной задачи. Предварительный просмотр показывает текущее состояние и предупреждения,
но не моделирует новые даты. Применение проверяет часы после пересчёта и сохраняет проценты
назначений при типе `0`; при нарушении выполняется попытка отмены без сохранения плана.

## Протокол изменений

Не изменяй план сразу по свободному тексту пользователя. Сначала прочитай актуальное состояние плана и сформируй предварительный просмотр: целевые задачи или ресурсы по `UniqueID`, старые и новые значения, затронутые связи, пересчёт дат, перегрузки и риск удаления данных.

Выполняй запись только после явного подтверждения пользователем именно показанного набора изменений. Перед первой записью в конкретный план за текущую сессию MCP создаёт резервную копию рядом с исходным `.mpp`; последующие изменения того же плана в этой сессии не создают новые копии. Затем повторно проверяй доступ и актуальность плана, применяй изменения, пересчитывай расписание и показывай результат с путём к резервной копии первой операции.

Удаление задач, ресурсов, назначений, зависимостей или базовых планов всегда требует отдельного предварительного просмотра и подтверждения, даже если входит в более крупный набор изменений.

Инструмент никогда не открывает и не закрывает Microsoft Project. Применение работает только с одним открытым `.mpp`; первая запись в план за сессию создаёт рядом копию с отметкой времени, затем все записи пересчитывают и сохраняют план. Не заменяй этот протокол прямыми вызовами `powershell.exe` или автоматизацией интерфейса.

Подробный порядок реализации описан в [references/roadmap.md](references/roadmap.md).

## Пользовательские текстовые поля задач

`outline` возвращает непустые поля `Text1`–`Text30` в объекте `text_fields`
по внутренним именам, независимо от названий колонок. Запись поддерживается
в `task:create` и `task:update`:
`{"kind":"task","operation":"update","task_unique_id":13,"name":"Фундамент API и SPA","text_fields":{"Text1":"PLT-002","Text2":"Примечание"}}`.
Пустая строка очищает поле; отсутствующие поля сохраняются. Допустимы только
`Text1`–`Text30` со строковыми значениями. Поля и название можно изменить одной
операцией. Перед сохранением значения перечитываются и сверяются; при ошибке
операция отменяется без сохранения. Протокол предварительного просмотра
и резервного копирования сохраняется.

Пакетный перенос названий и текстовых полей поддерживается через `task:update_many`:
`{"kind":"task","operation":"update_many","task_updates":[{"task_unique_id":13,"name":"Фундамент API и SPA","text_fields":{"Text1":"PLT-002"}}]}`.
Пакет ограничен названиями и текстовыми полями; даты, часы и назначения в него
не включаются. Список UniqueID проверяется до записи. При ошибке весь пакет
отменяется; сохранность часов и фактических дат проверяется до сохранения.


Для разбиения задачи с сохранением её строк, назначений, факта и связей
используй `task:wrap`: `{"kind":"task","operation":"wrap","task_unique_id":17,"name":"Стенд","child_name":"Существующая работа","text_fields":{"Text1":"INF-001"}}`.
Создаётся новая сводная строка над исходной; исходная становится её дочерней,
сохраняя UniqueID и работу. Её Text1 очищается, индекс записывается у сводной
задачи. Остальные часы, назначения и фактические даты всех исходных строк
проверяются перед сохранением; при ошибке операция отменяется.

Создание дочерней строки задаёт уровень непосредственно через
[Task.OutlineLevel](https://learn.microsoft.com/en-us/office/vba/api/project.task.outlinelevel),
чтобы свёрнутое представление не приводило к выбору соседней задачи.

## Разбиение по видам работ одной операцией

`task:decompose` создаёт новую сводную строку, оставляет исходную задачу первой
дочерней и создаёт остальные ролевые подзадачи в указанном порядке. Исходные
UniqueID, фактические часы и даты сохраняются; исходный Text1 переносится в
сводную строку, у дочерних Text1 пустой. Название `name` должно совпадать с
исходным названием. `expected_work_hours` защищает от изменения бюджета между
чтением и записью. Перед записью дополнительно проверяются актуальные
параметры исходной строки и назначений.

Пример переноса 40 ч фронтенда из исходного назначения в новую подзадачу:

```json
{
  "kind": "task",
  "operation": "decompose",
  "task_unique_id": 91,
  "name": "Исходная задача",
  "child_name": "Бэкенд",
  "expected_work_hours": 160,
  "text_fields": {"Text1": "EXAMPLE-001"},
  "source_assignment_work": [{"resource_unique_id": 11, "work_hours": 0}],
  "task_children": [
    {
      "name": "Фронтенд",
      "work_hours": 40,
      "assignments": [{"resource_unique_id": 11, "units": 1, "work_hours": 40}]
    },
    {"name": "Тестирование", "text_fields": {"Text2": "Оценка не задана"}}
  ]
}
```

Пример предполагает, что исходная задача содержит 120 ч бэкенда и 40 ч
фронтенда; инструмент проверит сохранение всех 160 ч. Набор исходных
назначений сохраняется, в перенесённом назначении остаётся нулевой Work.
Для исходной задачи без ресурсов вместо `source_assignment_work` можно
передать `source_work_hours`. Изменение исходных часов поддерживается только
для автоматической задачи с фиксированными единицами, `effort_driven:false`
и без фактической работы. Сумма исходной строки после перераспределения и
новых подзадач должна совпасть с прежним бюджетом.

Новые задачи с `work_hours` планируются автоматически; с ресурсами их
длительность рассчитывает Project. Без ресурсов часы не определяют
длительность. Если `work_hours` отсутствует, новая задача не получает оценки
и ресурсов, остаётся ручной в исходном окне дат; указывай это явно в Text2.
Не подставляй ноль вместо неизвестной оценки. Дополнительные зависимости
не создаются: после разбиения проверь, должны ли прежние последователи ждать
всю сводную группу вместо исходной строки.

Операция выполняется в одной транзакции отмены, проверяет иерархию, часы,
факт и назначения до сохранения. При ошибке проверки изменения отменяются.
Сохранение проверяется отдельно: `saved:false` означает, что изменения
могут уже находиться в памяти Project; перечитай план перед повторной
записью, чтобы не создать дубли. Предварительный просмотр и резервное
копирование выполняются по общему протоколу.

Для сокращения расхода токенов обрабатывай JSON `outline` внутри
`functions.exec` и выводи только нужный раздел или объект. Полное внутреннее
чтение пока остаётся. В проверке декомпозиции ссылки на задачи сохраняются
по UniqueID, чтобы не обходить коллекцию повторно для каждой строки.
Пустые даты новых задач читаются безопасно, ссылка на приложение
закрепляется на время операции. Активный ввод или диалог Project может
временно мешать COM; не приписывай любой сбой работе пользователя без
проверки и не повторяй структурную запись без чтения её результата.
